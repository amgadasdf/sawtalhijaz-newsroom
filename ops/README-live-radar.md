# تشغيل الرادار الحيّ من مشغّل GitHub (سحابة الشبكة المفتوحة)

## لماذا؟
شبكة صندوق الجلسة المعزول تحجب كل مضيفات المصادر (مسبار 0/3، أدلته في `reports/live-probe-2026-09-29.md`)،
والوحيد المسموح هو GitHub. لذلك تُنفَّذ طبقة الشبكة على مشغّل GitHub Actions (إنترنت كامل)،
بينما يبقى **المحرك نفسه بلا أي تعديل** ويبقى كاتب الذاكرة هو جلسة العمل.

## البنية
- `.github/workflows/live-radar.yml` — ملف قصير ثابت (يُضاف مرة واحدة من مالك المستودع؛ صلاحية الأبّ لا تسمح للجلسة بإنشائه).
  - **سببان للتشغيل:** إنشاء/تحديث ملف الـworkflow نفسه، أو دفع ملف `.radar-net/radar-*` (زناد يدوي).
- `ops/live-radar-runner.js` — المنفّذ الكامل (يُدار من الجلسة): الزمن الموثق، المسبار الثلاثي، أمر المالك حرفياً
  `node engine/cli.js radar --section "تريند-الشارع" --scope "السعودية" --depth "سريع" --record`، ثم اللوحة،
  ثم طباعة النتائج كاملة (SUMMARY_JSON + FULL_LATEST_JSON) ودفع النتائج للفرع (best-effort).
- الاسترجاع: artifact باسم `live-radar-output` + السجل الكامل + (عند السماح) دفع تلقائي للفرع.

## الأمانة والوسم
- المنفّذ هو مشغّل GitHub لا صندوق الجلسة — يُذكر ذلك صراحة في تقرير كل تشغيل وفي قيد الذاكرة.
- لا fixtures ولا بيانات مُصنّعة ولا نقل من نتائج المجلس: كل حرف يأتي من جلب حيّ حقيقي بنفس المحرك.
