## 4) دليل انقطاع الشبكة (لماذا `unverified` لا `header`)

```
$ curl -sS -m 10 -I https://sawtalhijaz.com/
curl: (35) OpenSSL SSL_connect: SSL_ERROR_SYSCALL in connection to sawtalhijaz.com:443

$ node -e '…fetch("https://sawtalhijaz.com/", {method:"HEAD"})…'
node fetch: TypeError | fetch failed | cause=ECONNRESET
```

المضيف يُفكّ ويقبل TCP لكنه يقطع TLS من هذه البيئة (سحابة التشغيل). لذلك:

- `fetchHeaderTime()` يحاول HEAD ثم GET، ويسجّل السبب الخام (`TypeError: fetch failed (ECONNRESET)`) داخل التنويه — لا فشل صامت.
- الأوضاع الأربعة أُثبتت **حتمياً بحقن fetch** (انظر القسم 2) بدل انتظار الشبكة: `env` (فارق 0ث)، `header` (فارق 90ث → اختير الهيدر مرجعاً حاكماً)، `manual` (فارق 7908ث)، `unverified` (فشل + لا يدوي).
- حقلة الهيدر ستعمل تلقائياً بلا تعديل كود في أي بيئة تسمح بالاتصال بـ `TIME_REFERENCE_URL`.

```
### node engine/cli.js settime "2026-09-24T09:00:00Z" --note "حقلة يدوية لاختبار البند 5"
الزمن: 2026-09-24T09:00:00.000Z | مصدر=manual | skew=7846ث | زمن يدوي معتمد من المالك — حقلة يدوية لاختبار البند 5 — المرجع الحاكم عند انقطاع الشبكة.
### node engine/cli.js settime --clear
الزمن اليدوي مُسح — iso=—
```

(`state/time-manual.json` ملف حالة مشروع، لا سرّ: `iso=null` بعد المسح.)
